### 0.5 官方候选分析后的 R1′ 修订决策（2026-10-05）

四个官方 case 在 `stage_opt` 和 `stage_before_common_techmap` 均不存在能够通过旧 R1 全部前提的有效候选，因此本节废止旧 R1 作为 v0.1 主规则；若与 0.1～0.4 的整字、内层 MUX 或死 cell 要求冲突，以本节为准。

1. v0.1 的唯一主规则改为 R1′：在选择 cell 数据入口的局部保护条件下，证明数据位为确定常量并替换该端口位。旧“内层 MUX 链旁路”R1 延后，不在 v0.1 实现。
2. v0.1 只使用当前 cell 的局部保护条件，不累积普通 MUX 链从区域根到入口的完整路径条件。
3. 分析 `$mux.A/B` 和 `$pmux.A/Bi` 的全部数据入口；保护条件分别为 `S=0`、`S=1`、全部 `Sj=0` 和 `Si=1`。
4. 允许逐位改写；相邻已改写位只在计划与日志中合并为连续字段，不要求整个数据入口全部成为常量。
5. 只替换原本不是常量、且已证明为确定 `0/1` 的数据位；不改写原本为 `x/z` 的位。
6. 比较器反推只实现 `(X==C)=1 => X=C` 和 `(X!=C)=0 => X=C`，其中 `C` 必须是无 `x/z` 的完全确定常量。
7. 只修改当前 `$mux/$pmux` 的端口位，不修改被引用信号的驱动及其他使用位置；共享数据源不是拒绝条件。
8. 在线成本门改为：至少一个非常量数据位被替换为常量，且不新增 cell、不修改选择网络和时序结构；不再要求删除 cell。
9. 某一数据位遇到不支持结构或无法证明时，只放弃该位；其他已经独立证明的位仍可生成计划。
10. 当前入口出现事实矛盾时，放弃该入口的全部改写并记录 `fact_conflict`；不得据此删除分支。

### 0.6 R1′ 证明引擎锁定决策（2026-10-05）

1. 每个经 `SigMap` 规范化的信号位只维护 `UNKNOWN/ZERO/ONE` 三种事实；同一入口内同一位同时得到 `ZERO` 和 `ONE` 时设置入口级 `fact_conflict`。
2. 局部保护条件直接作为分析初始事实注入，不为 guard 新增 RTLIL cell：`$mux.A` 注入 `S=0`，`$mux.B` 注入 `S=1`，`$pmux.Bi` 注入 `Si=1`，`$pmux.A` 注入全部 `Sj=0`。
3. 直接连接和 NOT 对已证明的确定 `0/1` 事实双向传播；不得据此传播 `x/z`。
4. AND/OR 使用确定性的单位传播。AND 支持“任一输入为 0 推出输出为 0”“全部输入为 1 推出输出为 1”“输出为 1 推出全部输入为 1”“输出为 0 且除一个输入外均为 1 时推出剩余输入为 0”；OR 使用严格对偶规则。
5. `$mux` 的选择端已知时，只在输出与被选数据端之间双向传播，未选数据端不参与该关系。
6. `$logic_*` 和 `$reduce_*` 只执行能唯一确定具体信号位的规则。允许 `reduce_or=0`、`reduce_bool=0` 推出全部输入位为 0，允许 `reduce_and=1` 推出全部输入位为 1，并允许“除一个输入位外均已知”时的唯一单位反推；仅知道“向量非零”但无法确定具体位时不得反推。
7. 比较器反推要求一侧为无 `x/z` 的完整常量，另一侧能一一对应到规范化信号位，且有效比较位宽、符号和扩展语义完全明确；复杂或不明确情形返回未知。
8. `ConstEval` 只承担已有输入事实下的正向求值；自定义工作队列承担保护条件、反向传播、比较器反推和证明记录，并把新事实重新入队。
9. 每个数据入口的硬预算为：最多 512 个组合 cell、8192 个规范化信号位、262144 次规则激活或队列事件。不使用墙上时间作为候选中止条件；任一预算耗尽时，尚未完成的证明返回未知。预算变更必须先更新方案并以批量实验为依据。
10. 每个事实记录目标信号位、目标值、推理规则、直接前提、来源 cell 和父事实编号。同一事实有多条证明时，保留“证明链更短，其次稳定编号更小”的确定性证明。

### 0.7 计划提交、测试与验收锁定决策（2026-10-05）

1. 证明结果先按数据入口收集，提交前必须按 `(cell, port)` 合并为端口改写计划；尤其 `$pmux` 的不同 `Bi` 切片可能共用同一物理 `B` 端口，不得分别覆盖式提交。
2. 同一物理端口位的相同目标常量去重；不同目标常量记为 `rewrite_conflict`，放弃涉及该位的数据入口，禁止依赖枚举顺序任选结果。
3. 不同 cell 间的数据依赖不构成计划冲突。每条 R1′改写必须独立证明保持目标 cell 的整体输出语义；所有计划仍必须来自同一只读快照。
4. 在任何写入前统一预检查全批计划。只要任一计划的目标 cell、端口、位宽或原连接与快照不一致，就放弃整个提交批次并记录错误，不允许部分写入。
5. 预检查通过后，不重新运行证明；按稳定顺序一次性提交合并后的端口计划。
6. 手写测试至少覆盖 16 类：`$mux.A`、`$mux.B`、`$pmux.A`、`$pmux.Bi`、case3 风格 `$eq` 反推、`$ne=0` 反推、部分位成功、共享数据源、重叠 PMUX 选择、原数据含 `x/z`、位宽或符号不明确、不支持 cell、事实冲突、三个资源预算边界、同一 `$pmux.B` 多分支同时改写、完全无优化机会。每例均检查结构、统计和 EQY。
7. 每次重要修改使用固定种子运行 100 个小型随机设计；阶段验收至少运行 1000 个。每个设计都执行综合与 EQY，并保存失败种子。
8. Pass 后自动检查：新增 cell 数为 0；只有计划中的 `A/B` 端口位变化；`S/Y`、参数、分支数量、DFF、存储器和模块端口不变；实际变化位与计划一致；原 `x/z` 位不变；Yosys `check` 通过。
9. 本节锁定后 G2 完成；下一阶段定义为 G3“最小原型验证”。G2 不以尚未实现的 LUT 收益为完成前提。
10. G3 通过必须同时满足：16 类微型测试全部通过；至少 1000 个固定种子随机设计全部 EQY；四个官方 case 全部 EQY；任何官方 case 的 LUT 不增加且至少一个减少；DFF、IO 等非目标资源不增加；时间和内存记录完整；不存在名称或源码位置硬编码。仅识别并替换 case3 的预期位而没有 LUT 收益，只能证明实现正确，不能进入最终默认流程。

## 1. 评测契约

### 1.1 已确认条件

1. 正式评测包含四个官方 case，各 case 的优化率分别计算后取平均。
2. 基线使用官方原版 Yosys；优化版本将自定义 Pass 编译进 Yosys 主程序，并在 `synth_intel.cc` 内调用。
3. 两边执行相同的 `synth_intel -family cycloneiv`，统一使用 ABC9。
4. 主优化指标是 ABC9 后的 `$lut` 数量；DFF、IO 等其他单元原则上不得增加。
5. EQY 比较原始 RTL 与 ABC9 后、仍以 `$lut` 表示的 ILANG 网表。默认分区无法完成时，允许使用整设计 miter，但必须真正完成证明。
6. 正式开发基于已确认的 Yosys 0.69，提交为 `9f75ca1f9834a39a863915b5dae0c7b1e33533bc`；G0 已在该版本完成。
7. eLinx 暂不进入算法高频评测闭环，其是否属于选题二强制验收环节仍待官方确认。

### 1.2 目标函数

对第 `i` 个 case：

```text
Ri = (LUTbase_i - LUTopt_i) / LUTbase_i
Ravg = (R1 + R2 + R3 + R4) / 4
```

优化的字典序目标为：

1. 所有 case 形式等价；
2. DFF、IO 等非目标资源不增加；
3. 最大化 `Ravg`；
4. 在前三项相同的情况下，降低运行开销和实现复杂度。

任何未完成证明、证明超时、遇到不支持结构或违反预算的候选都必须保持原样。

### 1.3 尚未确认的评测口径

- 时间是否最终计分，以及统计范围；
- 峰值内存的最终统计范围；
- eLinx 对选题二的强制输入、输出和验收内容。

这些问题不阻塞正确性优先的算法设计，但阻塞最终性能预算的锁定。

## 2. 设计范围

### 2.1 输入与输出

`pmux_opt` 的逻辑输入是已完成 `proc` 转换、尚未完成 PMUX 降低和 ABC9 映射的 RTLIL 设计。Pass 不读取或解析原始 Verilog 文本。

输入至少满足：

- `always/if/case` 已转换为 RTLIL cell 和连接；
- `$pmux/$mux/$eq` 等高层组合 cell 仍可识别；
- 设计尚未全部转换为 `$lut` 或厂商原语。

输出必须是功能等价、结构合法的 RTLIL 设计，可继续执行 `opt_clean`、后续技术映射和 ABC9。

物理插入位置必须位于 `proc` 之后、选择网络被降低及 ABC9 之前。首选位置已定为 `memory_map; opt -undriven -fine` 之后、公共 `techmap -map +/techmap.v` 之前，并在 `pmux_opt` 后显式调用 `opt_clean`。

### 2.2 首版作用域

首版以 `$pmux` 和普通 `$mux` 链为候选根节点，统一构造 `SelectionRegion`，可以分析其选择锥和数据锥中的：

- `$mux/$pmux`；
- `$eq/$ne`；
- AND、OR、NOT；
- 支持的 `$logic_*` 和 `$reduce_*`；
- 常量、直接连接和位切片。

首版不优化无法归入局部 `SelectionRegion` 的任意全局 MUX 网络，不跨越 DFF、存储器、黑盒和时钟边界，不直接优化 ABC9 后的 `$lut` 网络。

### 2.3 首版非目标

- 一般布尔综合器；
- 全模块 SAT 重写；
- 跨时序边界优化；
- 任意优先级网络重排；
- 在线反复调用 ABC9 评估每个候选；
- 未经成本验证的 ADD/BDD 全局结构重建；
- 针对文件名、模块名、cell 名或源码行号的硬编码；
- 按位或按字段拆分、复制或重排选择网络；仅改写现有数据端口位不属于拆分选择网络；
- 允许新增组合逻辑的 `lut-aware` 重写。

## 3. 核心概念

### 3.1 PMUX 模型

设 PMUX 数据宽度为 `W`、选择位数为 `N`：

```text
Y = PMUX(A, B0, B1, ..., B(N-1); S0, S1, ..., S(N-1))
```

- `A`：默认数据，宽度为 `W`；
- `Bi`：第 `i` 个分支数据，宽度为 `W`；
- `Si`：第 `i` 个选择条件；
- `Y`：输出，宽度为 `W`。

不得仅因 cell 类型为 `$pmux` 就假设所有选择条件互斥。但 R1 对 `Bi` 的改写只要求在 `Si=1` 时新旧数据等价，因为 `Bi` 只有在 `Si=1` 时才可能影响输出；因此 R1 不需要额外证明其他 `Sj=0`。涉及分支合并、重排或 one-hot 化时仍必须另行证明互斥或严格保持优先语义。

### 3.2 SelectionRegion 与保护条件

`SelectionRegion` 是选择网络的只读盘点表示。R1′以其中每个独立 `$mux/$pmux` cell 的数据入口为分析单位，至少记录：

```text
output
default_value
branches[] = { guard, value, priority_path }
source_cells[]
```

保护条件定义为该数据入口可能影响区域输出时必须满足的条件：

- `$pmux` 的 `Bi`：`Gi = Si=1`；
- `$pmux` 的 `A`：`Gdefault = AND_j(Sj=0)`；
- 单个 `$mux` 的 `B`：`G = S=1`；
- 单个 `$mux` 的 `A`：`G = S=0`；
- 普通 `$mux` 链的累计路径条件：仅为后续规则预留，R1′不使用。

`simplify_under_guard(data, guard)` 表示只在 `guard` 成立时分析当前数据入口的局部组合锥。v0.1 允许它逐位返回“已证明为 `0`”“已证明为 `1`”或“未知”；只为确定常量位生成端口替换计划，不新增逻辑。

### 3.3 局部组合锥

局部组合锥是从 `SelectionRegion` 的保护条件和叶子数据入口向驱动方向追踪得到的有界组合扇入子图，分为：

- **控制锥**：解释保护条件中的每个选择信号如何产生；
- **数据锥**：解释 `SelectionRegion` 的默认值和各分支值如何产生。

追踪在模块输入、DFF 输出、存储器、黑盒、不支持 cell、节点预算或深度预算处停止。共享逻辑可以参与证明，因为 R1′不修改其驱动；仍应记录锥外使用者用于诊断和未来规则。

### 3.4 事实域

首版内部按位维护事实，以便正确处理位向量逻辑。R1′可独立提交任意已证明的数据位，不要求同一入口的其他位也可证明：

```text
ZERO    已证明为0
ONE     已证明为1
UNKNOWN 当前无法证明
```

事实还应记录来源：直接常量、局部保护条件、结构推断或比较器反推。某一目标位遇到 `x/z`、多驱动或不支持语义时，该位返回 `UNKNOWN`，不影响其他独立位；同一入口出现互相矛盾的事实时，放弃该入口全部计划并记录 `fact_conflict`。SAT 证明来源仅为后续版本预留。

## 4. 总体算法

算法分为“只读分析”和“提交修改”两阶段。每次 Pass 调用只建立一次快照、完成一次分析并提交一批计划，内部不重新分析。分析期间不得直接修改当前设计，所有改写先形成候选计划；证明和成本门均通过后才一次性提交。

### 步骤 0：建立设计索引

对当前模块建立只读快照和索引：

1. 优先使用 Yosys `SigMap` 进行信号归一化以消除 wire 别名影响，并识别保持位宽、位序和逐位身份不变的透明连接；重排、复制、扩展和截断均不属于透明连接；
2. 优先使用 `ModIndex` 等现有基础设施建立或查询每个信号位的驱动者映射；
3. 优先使用 `ModIndex` 等现有基础设施建立或查询每个信号位的使用者映射；
4. 标记多驱动、时序边界、黑盒和不支持 cell；
5. 记录 cell 类型、参数、端口宽度和相关属性；
6. 生成稳定的模块、PMUX、分支和节点标识，保证枚举、冲突选择和日志可复现。

如果某个目标信号位存在无法解释的多驱动，相关候选必须跳过。

### 步骤 1：枚举选择 cell 与数据入口

按“模块稳定顺序、cell 稳定标识、端口稳定顺序”的确定性顺序遍历当前 selection 中的每个 `$pmux` 和普通 `$mux`。每个 cell 都是 R1′的独立分析对象，即使它同时位于普通 MUX 链内部，也不得因已归入某个 `SelectionRegion` 而跳过。`SelectionRegion` 仅用于结构盘点和后续规则。`$pmux` 需要读取并校验：

- `WIDTH`；
- `S_WIDTH`；
- `A/B/S/Y` 宽度关系；
- 各数据分支的位切片；
- cell 是否允许修改。

普通 `$mux` 需要读取并校验 `WIDTH/A/B/S/Y`。所有合法 cell 的 `A/B` 数据入口都进入便宜扫描；首版不因启发式分数低而永久丢弃，只决定分析顺序。

### 步骤 2：便宜机会扫描

不递归展开完整锥，先记录：

- 数据入口中已有常量位和仍为非常量的位数；
- 分支保护条件是否为常量；
- 保护条件是否直接由 `$eq/$ne` 驱动；
- 数据位是否依赖于也被局部保护条件约束的信号；
- 分支数量和数据宽度；
- 是否存在明显的浅层 AND、OR、NOT。

便宜扫描产生机会标签和分析优先级，不直接证明优化合法。

候选优先级原则为：潜在可常量化位越多、保护条件越直接、证明越便宜，优先级越高。优先级只影响顺序，不得改变结果集合。

### 步骤 3：提取局部组合锥

对进入深度分析的数据入口，按 cell、端口、位索引稳定顺序进行惰性提取：

1. 分别提取每个保护条件的控制锥；
2. 数据路径按目标位展开当前证明真正需要的节点；不因其他位不可证明而停止；
3. 合并重复节点但保留每条依赖路径；
4. 标注每个节点是否存在锥外使用者；
5. 标注模块输入、寄存器输出等自由边界；
6. 每个当前数据入口最多纳入 512 个组合 cell；遇到预算上限时停止扩展，并把尚未完成的位记为未知；
7. 与当前目标位证明无关的 `x/z`、多驱动或不支持 cell 不因此拒绝其他位。

提取失败只影响当前候选，不得导致整个 Pass 失败。

### 步骤 4：建立入口保护条件

仅根据当前选择 cell 建立当前数据入口的局部保护条件：

1. `$pmux.Bi` 使用 `Si=1`；不得无证明地加入其他 `Sj=0`；
2. `$pmux.A` 使用全部 `Sj=0`；
3. 单个 `$mux.B` 使用 `S=1`，单个 `$mux.A` 使用 `S=0`；
4. v0.1 不累积当前 cell 之外的普通 MUX 链路径条件。

这些保护条件用于证明“入口数据在可能被观察时，新旧表达式等价”，不是对整个选择网络进行 one-hot 声明。`parallel_case/full_case` 等属性不能替代实际路径条件。全局互斥证明不属于 v0.1 R1 流程。

### 步骤 5：便宜规则迭代到不动点

把局部保护条件直接作为初始事实加入工作队列，不在 RTLIL 中创建 guard 逻辑。`ConstEval` 只负责已有输入事实下的正向求值；自定义工作队列负责保护条件、反向传播、比较器反推和证明记录。每产生一个新事实，就重新激活受影响的规则，直到工作队列为空或达到硬预算。工作队列为空表示正常到达不动点；禁止使用固定传播轮数，也不是固定执行一次“三值传播→比较器反推→三值传播”。

每个数据入口最多分析 512 个组合 cell、8192 个规范化信号位和 262144 次规则激活或队列事件。不使用墙上时间作为候选中止条件。任一预算耗尽时停止该入口分析，尚未完成的目标位返回未知，不提交缺少完整证明的改写。

首版规则域包括：

1. 常量与保持逐位身份的直接连接双向传播；
2. NOT 对确定 `0/1` 双向传播；
3. AND/OR 的确定性单位传播：AND 支持“任一 0 推出输出 0、全 1 推出输出 1、输出 1 推出全 1、输出 0 且除一个输入外全 1 时推出剩余输入 0”，OR 使用严格对偶规则；
4. `$logic_not/$logic_and/$logic_or` 和 `$reduce_and/$reduce_or/$reduce_bool` 只执行能唯一确定具体输入位的正向或反向规则；“向量非零”但不能定位具体位时不反推；
5. 已知选择信号的 `$mux` 只在输出与被选数据端之间双向传播，不触碰未选数据端；
6. `(X == C)=1` 推出 `X=C`；
7. `(X != C)=0` 推出 `X=C`；

其中 `C` 必须是无 `x/z` 的完全确定常量，另一侧必须能一一对应到规范化信号位，并且有效比较位宽、符号和扩展语义完全明确。v0.1 不传播 `$xor/$xnor`、算术、移位、大小比较或其他未列入白名单的运算。

`(X == C)=0` 或 `(X != C)=1` 通常只能推出 `X != C`，不得擅自给 `X` 的各个位赋常量。

事实状态只有 `UNKNOWN/ZERO/ONE`。每条确定事实必须保存目标位、目标值、规则、直接前提、来源 cell 和父事实编号；同一事实存在多条证明时保留证明链更短者，长度相同时保留稳定编号更小者。当前入口内出现事实矛盾时，放弃该入口全部改写并记录 `fact_conflict`；v0.1 不利用矛盾推导分支不可达，也不删除分支。

### 步骤 6：发现 R1′ 改写机会

对每个 `$mux.A/B` 和 `$pmux.A/Bi` 调用 `simplify_under_guard(data, local_guard)`。对数据入口的每一位执行：

1. 原位已经是常量时只统计，不重复改写；原位是 `x/z` 时保持原样；
2. 原位是非常量时，尝试在局部保护条件下证明其为 `0` 或 `1`；
3. 证明成功则记录该位、常量值和完整证明来源；证明失败或遇到不支持结构时只跳过该位；
4. 相邻已证明位可以在计划和日志中合并为连续字段，但提交语义仍是精确位替换；
5. 不修改数据源驱动，也不修改同一信号的其他使用位置，因此共享数据源可以接受。

若入口内出现事实矛盾，则放弃该入口所有已收集位；不得据此删除该入口或选择分支。此步骤不发现不可达分支、重复分支、分支合并或结构重建机会。

### 步骤 7：局部证明

对每个非常量目标位 `D[k]` 建立两个互斥的证明义务，目标是证明其中之一：

```text
G => D[k]=0
```

或：

```text
G => D[k]=1
```

若不动点推断证明其中一个命题，可以为该位生成改写计划；两者均未证明则该位返回未知。若分析过程同时产生互相矛盾的事实，则按入口级 `fact_conflict` 处理。v0.1 不调用 SAT。

后续版本若经官方 case 证明确有必要，可以在保持相同证明接口的前提下增加 SAT 查询：

```text
证明 G => D[k]=1：检查 G AND NOT D[k] 是否不可满足
证明 G => D[k]=0：检查 G AND D[k] 是否不可满足
```

只有 `UNSAT` 可作为证明；`SAT`、超时、错误和未知都表示不得改写。SAT 得到的新事实可以重新加入工作队列，再运行一次不动点传播。以上 SAT 流程不属于 v0.1 实现范围。

### 步骤 8：生成改写计划

证明成功后只生成计划，不立即修改网表。计划至少包含：

- 目标 cell、端口 `A/B`；对于 `$pmux.B` 还要记录分支切片索引；
- 精确目标位索引，以及仅用于展示的连续字段分组；
- 每位原始信号、目标常量和证明记录；
- 所依据的局部保护条件；
- 原端口快照、位宽和必要属性；
- 代理成本变化和回滚信息；

所有计划必须由同一份只读设计快照生成。证明结果先按数据入口收集，再按 `(cell, port)` 合并；`$pmux` 的不同 `Bi` 切片不得分别覆盖式提交。修改同一端口不同位的计划合并；同一物理位目标常量相同则去重；目标常量不同则记录 `rewrite_conflict` 并放弃涉及该位的数据入口，禁止按枚举顺序任选结果。不同 cell 间的数据依赖不构成冲突，因为每条 R1′都必须独立证明保持目标 cell 的整体输出语义。

### 步骤 9：成本门

ABC9 是全局启发式映射器，Pass 内部的简单公式不能准确模拟其 LUT 结果。因此采用两层成本机制。

#### 9.1 在线保守门槛（constantize-only）

v0.1 默认只接受：

- 不新增组合或时序 cell；
- 不增加数据位宽；
- 不修改 `S` 网络、分支数、优先语义或数据源驱动；
- 至少一个原本非常量的数据端口位被证明并替换为 `0/1`；
- DFF、IO 和时序结构完全不变。

不要求改写后有 cell 立即死亡。这只能降低负优化风险，不能保证 ABC9 后 LUT 一定减少。

#### 9.2 离线真实校准

开发阶段对规则执行完整 `synth_intel -family cycloneiv` 和 ABC9，记录四个 case 的实际 `$lut` 变化。进入最终默认规则集至少要求：四个 case 全部 EQY 通过、任何 case 的 LUT 不增加、至少一个 case 的 LUT 减少；若最终官方口径允许其他权衡，再单独修订。

允许“新增少量逻辑换取更少 LUT”的 `lut-aware` 模式不属于 v0.1，必须在 R1′的 `constantize-only` 基线和消融实验证明确有必要后另行立项，并单独定义成本模型和实测准入条件。

### 步骤 10：提交改写

只有证明门和成本门都通过的无冲突计划才提交。提交时必须：

1. 只在当前 `$mux/$pmux` 的目标 `A/B` 端口中替换计划列出的精确位；
2. 不修改区域的分支数量、优先顺序、`S` 连接或 `$pmux.S_WIDTH`；
3. 不修改目标位原信号的驱动及任何其他使用位置；
4. 不改变 DFF、IO、时钟、复位和存储器语义；
5. 保留必要属性和源码定位信息；
6. 保证设计在任意提交中途都不会被后续分析读取。

在任何写入前，必须对全批计划统一预检查目标 cell、端口、位宽、位索引及原连接是否与快照一致。任一计划不一致就放弃整个批次并记录错误，不允许部分写入。预检查全部通过后，不重新运行证明，按稳定顺序一次性提交合并端口。提交后仍由标准清理处理可能自然失去使用者的逻辑，但产生死 cell 不是 R1′的必要条件。

### 步骤 11：标准清理与一致性检查

`pmux_opt` 返回后，由综合流程紧接着显式执行标准清理和检查；Pass 内部不得调用 `opt_clean`：

- `opt_clean` 删除改写后自然失去全部使用者的普通 cell 和 wire；R1′不重复实现通用死逻辑删除；
- Yosys 结构检查确认端口宽度、驱动和层次合法；
- 重新统计 `$pmux/$mux/$eq` 等结构变化；
- 不在 `pmux_opt` 内调用或重复实现通用死逻辑删除。

### 步骤 12：输出诊断与度量

每次运行至少记录：

- 扫描 `$pmux` 数、普通 `$mux` 数、数据入口数和数据位数；
- 深度分析的数据入口数、目标位数及跳过原因；
- 保护条件的来源、形式和构造结果；
- 各推断规则产生的事实数；
- 证明为 `0`、证明为 `1`、未知和入口事实冲突的数量；
- SAT 调用、UNSAT、SAT、超时和错误数；v0.1 应全部为零；
- 各重写规则候选位数、接受位数、连续字段数和拒绝原因；
- 实际修改的 cell、端口、分支切片和位索引；
- `opt_clean` 自然删除的 cell 数，仅作观测而非准入条件；
- Pass CPU 时间和内存；
- ABC9 后 LUT、DFF、IO；
- EQY 结果。

## 5. v0.1 规则目录

### R1′：局部保护条件下的数据位常量化

结构：任意合法 `$mux.A/B` 或 `$pmux.A/Bi` 数据入口中，存在原本为非常量、但在当前 cell 的局部保护条件下可证明为常量的数据位。

局部保护条件：

1. `$mux.A`：`S=0`；`$mux.B`：`S=1`；
2. `$pmux.A`：全部 `Sj=0`；`$pmux.Bi`：`Si=1`；
3. 不累积当前 cell 外部的 MUX 链路径，不假设 PMUX 全局互斥。

前提：

1. 对目标位 `D[k]` 已证明 `G => D[k]=0` 或 `G => D[k]=1`；
2. 原位不是常量，也不是 `x/z`；
3. 比较器反推只使用 `(X==C)=1 => X=C` 或 `(X!=C)=0 => X=C`，且位宽、符号、扩展语义明确；
4. 当前入口没有事实矛盾，目标 cell、端口、位索引和原快照仍匹配；
5. 在线 `constantize-only` 成本门通过。

改写：只把当前 cell 数据端口的目标位替换为已证明的 `0/1`。允许逐位改写；连续字段仅用于计划和日志压缩。不修改数据源驱动、其他使用者、选择网络、分支数或时序结构。某一位未知只跳过该位；入口事实矛盾则放弃整个入口。

状态：v0.1 唯一启用的主规则。结构范围、保护条件、逐位改写边界与失败回退已锁定；精确传播规则、资源预算和 ABC9 实测准入仍在 G2 讨论。

### R1-old：路径条件下绕过内层 MUX

状态：官方四个 case 在两个候选阶段均未发现满足全部前提的有效候选，已从 v0.1 延后。未来若恢复，必须另行定义累计路径条件、独占性、整宽旁路、死亡链确认及成本门，不能复用 R1′的宽松共享条件。

### R2：全局不可达 PMUX 分支

结构：某 `Si` 在所有输入下恒为 0。

前提：必须全局证明 `Si=0`，不能只在其他分支路径下证明。

改写：删除对应的 `Si` 和 `Bi` 切片，调整 `S_WIDTH`。

状态：v0.1 禁用；作为后续候选规则保留。

### R3：分支数据与默认数据相同

结构：`Bi == A`。

风险：在选择条件重叠或具有特殊 PMUX 语义时，简单删除分支可能影响其他分支的可见性。

状态：v0.1 禁用；必须在 PMUX 语义和互斥前提锁定后再决定。

### R4：重复数据分支合并

结构：`Bi == Bj`，尝试合并选择条件。

风险：可能新增 OR，减少 MUX 却不减少 LUT；还依赖分支语义。

状态：后续规则，v0.1 禁用。

### R5：决策树/ADD 结构重建

状态：后续研究方向，v0.1 不实现。只有在简单删除型规则无法达到目标且成本模型已经由 ABC9 实验校准后才讨论。

## 6. 正确性不变量

任何实现必须持续满足：

1. 模块端口、DFF、IO、时钟和复位不变；
2. 不产生新的锁存器或时序状态；
3. 不改变不相关输出；
4. 不删除仍被共享的节点；
5. 不把 `UNKNOWN` 当作 0 或 1；
6. 不把属性提示当作唯一证明；
7. 不在位宽、符号或扩展语义不明确时反推比较器输入；
8. 不因 SAT 超时或失败而执行改写；
9. 重写后的设计必须通过 Yosys 结构检查；
10. 所有回归和官方 case 必须通过 EQY。
11. R1′只改当前 cell 的计划位，不修改共享信号驱动或其他使用位置；
12. 原端口中的 `x/z` 保持原样，不能借保护条件把它们当作确定 `0/1`；
13. `$pmux.Bi` 的证明不得依赖未经证明的其他 `Sj=0`，从而在选择位重叠时仍保持原语义。

## 7. 测试与验证策略

### 7.1 手写微型测试

R1′至少建立以下 16 类测试；每例都必须检查改写结构、Pass 统计和 EQY：

1. `$mux.A` 可常量化；
2. `$mux.B` 可常量化；
3. `$pmux.A` 默认入口可常量化；
4. `$pmux.Bi` 分支入口可常量化；
5. case3 风格的 `$eq` 反推；
6. `$ne=0` 反推；
7. 同一入口部分位成功、部分位未知；
8. 共享数据源只修改当前端口；
9. PMUX 选择条件重叠时仍保持原优先语义；
10. 原数据含 `x/z` 时相应位保持不变；
11. 位宽、符号或扩展语义不明确时拒绝反推；
12. 遇到不支持 cell 时相关位返回未知；
13. 入口事实冲突时整入口回退；
14. 512-cell、8192-bit 和 262144-event 三类预算边界；
15. 同一 `$pmux.B` 端口的多个分支同时改写且正确合并；
16. 完全没有优化机会时设计保持不变。

R1′还必须包含来自官方 case3 模式的正例：比较器保护条件把同一数据字的若干位确定为常量；预期至少覆盖已定位的 7 个可替换位。该正例验证“按位成功、共享源不改、其他位保持原样”，而不是预设 LUT 一定下降。

### 7.2 随机测试

用于发现崩溃、位宽错误、共享逻辑误删和不等价。每次重要修改使用固定种子运行 100 个小型随机设计；G3 阶段验收至少运行 1000 个。每个设计都必须综合成功且 EQY 通过，并保存失败种子以便复现。随机用例不要求 LUT 下降。

### 7.3 官方四个 case

用于确定插入位置、规则优先级、实际 LUT 收益和最终得分。不得按名称或源码位置硬编码。

### 7.4 开源 RTL

用于证明工程泛化和稳定性，优先选择包含 case 译码、总线选择和复杂 MUX 网络的设计。它不代替官方 case 的评分结果。

### 7.5 验证层级

1. Pass 前后 RTLIL 局部结构检查：新增 cell 数必须为 0；只有计划中的 `A/B` 端口位允许变化；`S/Y`、参数、分支数量、DFF、存储器和模块端口必须不变；实际变化位必须与计划一致；原 `x/z` 位必须不变；Yosys `check` 必须通过；
2. 微型用例全设计 EQY；
3. ABC9 后 `$lut` ILANG 与原始 RTL 的 EQY；
4. 四个官方 case 批量回归；
5. 是否需要补充 eLinx 材料以最新官方答疑为准；在正式确认前不把它纳入核心算法验收闭环。
