# 给 B 的 M1 接口问题

冻结文档已规定需要稳定原因码、计划、统计、物理位和分支号，但尚未给出可解析的机器日志 schema。C 已实现独立 adapter 边界，需 B 明确以下内容后联调，不由 C 猜测：

1. Pass 的命令名、输入/输出快照命令，以及未触发时退出状态。
2. 每条计划如何机器读取：模块与 cell 稳定标识、A/B 端口、零基物理位、`$pmux.Bi` 分支号、旧值、新常量、证明编号，以及被放弃入口。
3. 扫描 cell/入口/位、深度分析、已证明 0/1、未知、候选、接受、提交、去重、冲突、SAT 零计数、CPU/内存的精确字段名与单位；`changed_bits` 是否专指实际提交物理位。
4. 除已冻结的 `fact_conflict`、`rewrite_conflict` 外，比较器宽度/符号拒绝、不支持 cell、原 `x/z`、三个预算耗尽和无机会的原因码及计数口径。
5. 512 cell、8192 bit、262144 event 的边界是否按 `>=` 停止；14c 的事件计数达到阈值需 A/B 实测确认。预算耗尽时保留完整证明位的日志形式。
6. 全批快照预检查失败的原子零写入结果如何上报，以便 C 验证。

截至 B 分支 `90bc8c902`，`pmux_opt` 已报告汇总 `writes`、`planned`、`commit` 和原因码，但尚无逐物理位机器计划。C 已只读编译该提交的副本并运行 UNKNOWN 桩 19 例（全部零写入），强制 `-stub-zero` 在 `01_mux_a` 报告 `planned=2 writes=2`。强制桩不保证等价；C 的 `fixture-stub` 是预定计划重放，也不代表 A 的证明。收到逐位机器接口后，替换外部适配命令即可，不能改期望语义。
