# M0 三人协作启动检查清单

## 1. 先理解两个“基准提交”

必须同时记录两个哈希，不能混称“基准”：

1. **上游算法基准**：Yosys 0.69 的固定提交 `9f75ca1f9834a39a863915b5dae0c7b1e33533bc`。它用于证明团队代码从正确版本起步。
2. **团队开发基准**：把两份冻结方案、目录骨架和接口契约加入团队仓库后的提交。A、B、C 三条功能分支必须从这一完全相同的提交创建。

## 2. 建立唯一中央仓库

推荐在 GitHub、Gitee 或学校 GitLab 创建一个**空的私有仓库**，例如 `pmux-yosys`。创建时不要自动生成 README、License 或 `.gitignore`，避免产生与 Yosys 历史无关的根提交。

中央仓库应以完整 Yosys 0.69 源码仓库为主体，而不是只上传一个 Pass 文件。不要提交以下生成物：

- Yosys 构建目录和安装目录；
- 官方基线产生的日志、网表和 EQY 工作目录；
- 下载包、可执行文件和大型临时文件；
- 未确认允许分发的官方输入。

## 3. 由 B 在 WSL 中准备独立团队仓库

`E:\嵌入式比赛\official_baseline\official_baseline\toolchain\yosys-v0.69-src` 属于基线工具链，必须保持只读，不能改远端、建开发分支或编写Pass。团队开发仓库必须在WSL Linux文件系统中另建干净克隆。

优先从官方仓库重新克隆：

```bash
mkdir -p ~/work
cd ~/work
git clone --recurse-submodules https://github.com/YosysHQ/yosys.git pmux-yosys
cd pmux-yosys
git checkout 9f75ca1f9834a39a863915b5dae0c7b1e33533bc
git submodule update --init --recursive
```

如果网络不可用，可以从现有只读源码做本地克隆，但仍必须生成新的开发目录：

```bash
mkdir -p ~/work
git clone --recurse-submodules "/mnt/e/嵌入式比赛/official_baseline/official_baseline/toolchain/yosys-v0.69-src" ~/work/pmux-yosys
cd ~/work/pmux-yosys
git checkout 9f75ca1f9834a39a863915b5dae0c7b1e33533bc
git submodule update --init --recursive
```

然后只读核验：

```bash
git status --short
git rev-parse HEAD
git submodule status
git remote -v
```

必须满足：工作区干净，`HEAD` 等于：

```text
9f75ca1f9834a39a863915b5dae0c7b1e33533bc
```

若不相等或不干净，停止，不要用 `reset --hard` 清理；另建干净克隆。

确认后，将官方仓库设为 `upstream`，团队私有仓库设为 `origin`。如果是网络克隆，先把原 `origin` 改名；如果是本地克隆，则删除指向本机路径的 `origin` 后重新添加。最终必须由 `git remote -v` 明确显示两个远端。把下面占位地址替换为真实地址：

```bash
git remote rename origin upstream
git remote set-url upstream https://github.com/YosysHQ/yosys.git
git remote add origin <TEAM_REPOSITORY_URL>
git tag -a pmux-upstream-v0.69 9f75ca1f9834a39a863915b5dae0c7b1e33533bc -m "Pinned Yosys 0.69 baseline"
git switch -c integration/g3 9f75ca1f9834a39a863915b5dae0c7b1e33533bc
```

在 `integration/g3` 中加入且只加入：

- `PMUX优化技术方案_v0.1.md`；
- `G3三人并行分工与接口契约.md`；
- 本检查清单；
- 冻结的共享接口目录骨架；
- 必要的基线脚本和输入哈希清单。

然后形成团队开发基准：

```bash
git add <上述文件和目录>
git commit -m "docs(pmux): freeze v0.1 design and G3 collaboration contract"
git rev-parse HEAD
git push -u origin integration/g3
git push origin pmux-upstream-v0.69
```

把最后一次 `git rev-parse HEAD` 的完整40位哈希记录为 `TEAM_BASE_COMMIT`。

## 4. 创建三条独立分支

由 B 从同一个团队开发基准创建并推送：

```bash
git branch feature/a-proof-engine <TEAM_BASE_COMMIT>
git branch feature/b-pass-rewrite <TEAM_BASE_COMMIT>
git branch feature/c-verification <TEAM_BASE_COMMIT>
git push -u origin feature/a-proof-engine
git push -u origin feature/b-pass-rewrite
git push -u origin feature/c-verification
```

三人分别克隆到自己的 WSL Linux 文件系统中，不建议在 `/mnt/c` 或 `/mnt/e` 内长期编译：

```bash
git clone --recurse-submodules <TEAM_REPOSITORY_URL> ~/work/pmux-yosys
cd ~/work/pmux-yosys
```

然后各自只切换自己的分支：

```text
A：git switch feature/a-proof-engine
B：git switch feature/b-pass-rewrite
C：git switch feature/c-verification
```

每人都执行：

```bash
git submodule update --init --recursive
git merge-base --is-ancestor 9f75ca1f9834a39a863915b5dae0c7b1e33533bc HEAD
git rev-parse HEAD
git status --short
```

第一条命令返回码必须为0；首次切换分支后的 `HEAD` 必须等于同一个 `TEAM_BASE_COMMIT`，状态必须为空。

## 5. 再次确认工具版本

基线工具与开发工具必须分开：

- **基线工具**：永远使用未修改的Yosys 0.69安装目录产生基线结果；
- **开发工具**：从各自功能分支构建，允许包含团队提交，但必须确认上游祖先仍是指定0.69提交。

每台机器记录：

```bash

<BASELINE_INSTALL>/bin/eqy --version
<BASELINE_INSTALL>/bin/sby --version
<BASELINE_INSTALL>/bin/yosys-abc -v

```

目标工具口径：

```text

EQY v0.69，commit 4a72eb94fc253062464afee4d0018359017bb846
```

操作系统小版本、CPU、时间和峰值内存可以不同；Yosys/EQY/SBY/ABC版本、输入哈希、综合命令、LUT/DFF/IO和EQY结果必须一致。
